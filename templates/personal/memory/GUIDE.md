# Everyday topic memory

Read only the needed scenario. Ordinary discussion needs no work orchestrator, START, task matrix,
session transcript or repeated installation. Existing topic memory remains the current source.

## New or undecided topic

After confirmed core setup, ask the coordinator to create a selected topic in an agreed location.
For an undecided subject, an optional layout is `inbox/<stable-topic-id>/`; settled subjects may use
`topics/<stable-topic-id>/`. Each folder has its own AGENTS.md and memory/INDEX.md, BRIEF.md and
tasks/main/HANDOFF.md. A temporary name is sufficient; do not invent a final goal or classification.
The stable ID survives a rename. Keep only this topic's confirmed facts, questions and next step.
One store-wide inbox handoff must not mix unrelated conversations. A store registry contains only
requested navigation; it is not a shared personal profile or permission to open its other entries.
Installed topics need no repeat setup; create an independent task only when its goal needs a separate handoff.

## Continue in another chat or AI system

Select this topic folder or a reviewed portable copy, not the whole personal store. Give the agent:

> Work only in the supplied topic. Read AGENTS.md, memory/INDEX.md, memory/BRIEF.md and the selected
> task handoff. Restore the current goal, confirmed decisions, unknowns and next action; preserve WIP.
> Do not open sibling topics, a shared profile or linked external material without a relevant request.

The agent checks topic identity, directory/copy, dates/sources and actual remaining work. Instructions
must be supplied explicitly if the client does not discover AGENTS.md. A past chat cannot be restored
beyond saved records. With read-only attachments, return an exact proposed update for manual saving;
do not claim it was saved. Choose one writable current copy before editing from several clients.

## Move or merge selected topics

Name the exact source and destination; a merge requires authorization for both topics. If either
is unspecified/inaccessible, ask for that input rather than searching siblings. Preserve source files,
unfinished work and provenance before a move/merge; no unknown file is disposable.
For a move, retain the topic ID, update affected relative links/current entry and client folder binding.
For a merge, choose one canonical current topic and reconcile facts/decisions with sources/dates.
Do not overwrite a conflicting file or choose truth by newest timestamp. Keep both accounts until
the user resolves a material conflict; unresolved facts stay unknown. Update affected indexes/handoffs
and mark old entries superseded with an explicit destination. Such a pointer grants no wider access.
Verify links and continuation from the destination before retiring a source. Keep originals until
preservation and recovery are verified; no automatic deletion or rewriting of historical evidence.

## Stale facts and archive

Store important facts with source/date and status: confirmed, hypothesis, superseded or unknown.
A later conversation or file timestamp does not itself invalidate a fact. Verify only facts that
matter to the current request; mark contradictions/expiry explicitly and retain their origin/history.
Avoid repeating the same fact in BRIEF, handoff and sessions. Save a short session note only when useful.
Archive by marking the task/topic inactive in its current index and linking the retained outcome,
open questions and resume condition; default to leaving files in place. Physical relocation is a
separate selected action with link/binding checks. Do not load archived topics routinely or delete
them by age. Resume from the current entry, checking whether old decisions still apply.

## Portable copy and cloud

Use UTF-8 text and relative links within one selected topic; include referenced in-topic documents
needed for continuation. List unavailable external inputs as gaps; do not follow links to export
other topics or download cloud sources automatically. Exclude secrets, shared profiles, coordinator
service memory, unrelated topics and private logs; review the exact file list and content before sharing.
Cloud sync/upload and recipient/provider permissions require the selected destination and current authority.
Never use the public OCMI repository as personal storage. A folder/ZIP exclusion alone is no content scan.

For transfer, save a checkpoint and stop concurrent writing; copy only the selected files, compare
contents/hashes and resolve local links. Mark which copy is current and the other's revision/source.
Sync conflicts retain both copies; merge changes deliberately before continuing, not last-write-wins.
Directory links/symlinks and absolute paths must not silently include material outside the selected topic.
Without required linked files or write access, report incomplete/manual transfer; do not claim full recovery.

Folders and instructions limit intended context, not technical access. Verify the client's allowed
folders, connected sources, sharing and automatic memory separately, without opening another topic
as a test. Cloud/provider behavior is not certified by Markdown or synthetic file checks.

## Long wait or interruption

Distinguish executing, waiting for a named external event and no observed progress; silence is not
proof of a hang. Keep the operation ID/cursor, latest evidence, remaining work and next event/check
in the current handoff. Reuse the same operation; do not start a duplicate on resuming.
Bound the observation interval/deadline; without a local rule stop after three unchanged polls in a
turn and save a checkpoint. No unrequested notifications, scheduled monitoring or background work.
