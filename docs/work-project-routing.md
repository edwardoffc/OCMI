# Neutral work-project routing

OCMI system 1.3.2. This is a routing rule, not a user profile or development assignment.
Use in an optional client-level instruction file with an explicitly configured system source path.
Do not install a global rule automatically.

When the user identifies a specific project as a work project (“this is a work project” or equivalent),
select the orchestrator/worker/read-only consultant, file-memory and code-map profile.
Discussing this phrase as an example does not select the current folder.

1. Classify the selected target using only applicable instructions and its declared OCMI entry.
   An ordinary AGENTS.md or unfilled template is not proof of an operational OCMI installation.
2. Existing operational installations use their own instructions, memory and current assignments.
   Do not force coordinator setup, overwrite templates, duplicate PLAN or upgrade without a request.
3. Every new installation is performed by an initialized installation coordinator.
   Verify explicit source/service paths, client project/folder binding and current startup/handoff evidence.
   If missing or unconfirmed, defer target installation and hand the request to the coordinator.
   Do not copy profiles, create memory or inspect code/tests while prerequisites are pending.
4. For core setup read only the selected edition's BOOTSTRAP.md, VERSION.md, README and needed
   neutral setup guides/templates. Do not load source docs/memory, INDEX/PROFILE or private topics.
   Explain obtaining/reusing the local system, binding its client project and starting its coordinator.
5. The confirmed coordinator uses the selected edition's templates/work/INSTALL.md.
   Keep the same deferred target/scope; already-authorized actions need no repeated permission.
   Ask for missing paths; an unavailable source does not authorize disk scans or neighboring access.
6. Target installation authority does not select unspecified core locations or authorize client changes,
   chats/messages, models, background work, publication or production. Current user instructions prevail.
   Source locations and registry pointers do not grant access or inherit other projects' policies.

After installation the target uses its own memory for routine work.
A lightweight new topic uses the same core prerequisite in templates/personal/INSTALL.md.
Instructions describe a workflow; they do not prevent manual copying or enforce filesystem isolation.
