# OCMI-ONBOARD-013: optional guided setup

## Contract

Owner: current source-maintenance chat. Authority: direct request to implement the setup
route as a new release, with the explicit correction that users choose independent options.
Scope: neutral source instructions, bilingual guides/coordinator templates, validation and
new distributions. No user-store installation, folder move, project upgrade or publication.

Outcome: a user attaches the downloaded repository or supplies its URL; the agent gives
a brief orientation and offers folder organization, coordinator memory, personal storage,
project integration or explanation only. Configuration follows the selected current request.
System 1.3.0 is additive; work 1.2.2/lightweight 1.2.1 and protected packages are unchanged.

Criteria: setup route precedes source development; minimum orientation inputs; no inferred
write/scan/download authority; independent choices; explicit capability/source limits;
private self-contained optional coordinator memory; preserve existing setup paths/WIP;
matching en/ru instructions; complete new ZIPs and unchanged previous releases.
Checks: docs, workflow, localization, onboarding positive/negative clauses and scoped paths,
release byte inventories/hashes, diff. Behavioral scenarios are recorded, not claimed run.

Preservation: prior development PLAN/handoff edits were backed up locally and remain.
Work/lightweight sources and existing archives/receipts are protected by their current hashes.
Release files are permanent. Local baseline/validation evidence is ignored, owned by the
maintainer, retained until delivery and recovery verification; no automatic deletion.
