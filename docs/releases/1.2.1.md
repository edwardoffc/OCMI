## Completion scenarios

Manual consistency review using fictional situations.
No real resources were deleted; model/deletion-tool behavior was not tested.

| Situation | Decision under 1.2.1 |
| --- | --- |
| Small edit, no temporary resources | Reuse context; after integration, done with "no resources created" |
| Accepted but not integrated | Acceptance stands; do not declare full closure; retain required resources |
| R2 with suitable R1 copy / another owner's active copy | Reuse own copy; do not take the other; baseline change requires revision |
| Untracked/ignored, unknown WIP, or open finding | Preserve unknown/unique work and evidence; pending or justified keep |
| Main copy/another task uses temporary path | Preserve resource/dependency; resolve and check affected environment before closure |
| Shared cache or reproducible build | Keep shared cache; verify build reproducibility before authorized deletion |
| Squash/cherry-pick, SHA only | Verify actual integration and accessible data/history; SHA is not a backup |
| Supported deletion refused / no permission | Do not force; pending with reason, owner, and required decision |
| Cleanup pending, then environment/config changes | Acceptance stands; rerun affected check, not the whole suite for reporting |
| Old package without cleanup or link to closing copy | Unknown status; package unchanged; current decision/recovery route in current memory |
