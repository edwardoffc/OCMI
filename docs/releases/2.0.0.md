# OCMI 2.0.0 candidate

This bilingual candidate aligns the native verified-home entry with the work,
personal, and legacy coordinator profile inputs. ReadyKit remains the only
native package authority; profile ZIPs are coordinator inputs, not complete
installations.

The current [profile receipt](2.0.0-workflow-r4.json) preserves the original
receipt and archives. Exact optional tool references and the compact native
workflow are described in the installed runtime guides.

After explicit native binding, `context.inspect` may report fresh operational
facts or a verified derived ready START. Main must explicitly deliver that view;
it is not approval, semantic dependency analysis, or
a replacement for the required whole semantic Contract and inputs. Keep one semantic
PLAN, rationale, unresolved questions, Result, and Acceptance; do not copy
derived task or machine state into Markdown after each command.

New native homes use `OCMI_Sync/coordinator` with local machine-only binding.
The eight-file coordinator template is retained solely for legacy compatibility
and is not a new-native installation route. Personal topic memory remains
optional, selected-scope portable files, normally under `OCMI_Sync/personal`.

This is a source candidate, not a stable release or pilot acceptance. It makes
no claim of universal tool enforcement, measured savings, or completed
cross-platform qualification.
