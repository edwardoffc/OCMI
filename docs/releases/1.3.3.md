# OCMI 1.3.3 — compact tasks and causal checks

Release date: 2026-10-13. [English](1.3.3.md) · [Русский](../../locales/ru/docs/releases/1.3.3.md).

System 1.3.3 includes work protocol 1.2.3, rules revision 2026-10-13.
Coordinator/setup 1.3.2 and lightweight 1.2.1 remain unchanged.

The orchestrator selects a compact card for bounded reversible low-risk work.
The same Contract/Result/Acceptance, task identity, scope, baseline/WIP, protected inputs,
coverage, evidence, owner and cleanup remain. Sensitive or uncertain changes use the full card.
Inline criterion-to-check coverage avoids a separate matrix for compact tasks.

Existing validated checks cover requirements first; new tests fill uncovered requirements/risks.
Relevant cheap checks precede expensive CI; mandatory project gates and issued checkers still apply.
Behavior changes need a real consumer path in isolated conditions; documentation does not need product builds.
A green retry alone is not causal resolution. Preserve failed evidence and classify the cause;
confirmed transient infrastructure can close under project policy with evidence.
Before repeated substantive rework, record the cause/hypothesis, changed approach, next diagnostic and expected evidence.
Verified continuation reads deltas; new or uncertain context restores mandatory inputs.

## Distribution and verification

Two new work ZIPs contain 20 files each. Existing coordinator/lightweight editions and all prior
archives/receipts are preserved. [Component receipt](1.3.3-components.json) · [Distributions](../../releases/README.md).

[Acceptance](../memory/tasks/OCMI-FLOW-018/HANDOFF.md) records source checks, negative mutations,
translation review, exact source/ZIP agreement, archive preservation and privacy scanning.
The new check-flow validates both languages and rejects missing compact fields/schema/policy clauses.
The existing suite covers routing, localization, installation, platform paths and private exclusions.
These checks establish instruction/file safeguards, not actual model behavior or token/time savings.
Delivery requires native Windows, macOS Apple Silicon and Intel CI, protected-main integration,
and tag/source/asset verification. Final delivery evidence is recorded separately from source acceptance.

No installed project, local private memory, role/skill expansion, model run or project CI migration is included.
Existing assignments keep their fixed contract/checker. Adoption in an installed project is a separate explicit upgrade.
