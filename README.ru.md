# ОКПИ

[English](README.md) · **Русский**

ОКПИ хранит выбранный контекст проекта в файлах, чтобы новый чат продолжал работу с явной областью и текущим handoff. См. [установку](locales/ru/docs/install-system.md), [структуру](locales/ru/docs/layout.md) и [использование](locales/ru/docs/usage.md).

## Начните с готового комплекта

1. Получите или переиспользуйте проверенный подходящий ReadyKit; URL или скачанные исходники служат для знакомства, а не являются установленной копией.
2. Проверьте доверенную контрольную сумму архива, распакуйте его в пустую выбранную папку установки и выполните `system/bin/ocmi[.exe] install --home ABS`.
3. Координатор установки выполняет `ocmi coordinator prepare --home ABS --language en|ru --client-project NAME`, создавая локальный стартовый prompt.
4. Создайте или переиспользуйте проект клиента, привязанный к этой папке установки, откройте отдельный чат координатора и передайте `local/bindings/coordinator/STARTUP.md`.
5. Координатор проверяет текущую связь и записывает явное локальное подтверждение через `ocmi coordinator confirm`; лишь затем доступны отдельный выбор личного хранилища и внедрение в проект.

Открытие ссылки ничего не устанавливает и не разрешает изменения. Сохраняйте занятые папки и действующие установки; прежние профили являются входами совместимости, а не маршрутом новой установки. Публичная часть находится в `system/`; `OCMI_Sync` содержит выбранные переносимые данные координатора, а `local/` — состояние конкретной машины.

### Из ссылки

Передайте чату [ссылку на репозиторий ОКПИ](https://github.com/edwardoffc/OCMI) и попросите изучить ОКПИ. Чат может помочь получить проверенный подходящий ReadyKit; сама ссылка не запускает программу и не устанавливает систему.

### Из скачанной копии

Откройте папку скачанных исходников в чате или проекте и попросите изучить ОКПИ. Исходники помогают получить подходящий ReadyKit, но архив исходников не становится установкой. Оба входа продолжаются через [каноническое руководство](locales/ru/docs/install-system.md).

## Что даёт ОКПИ

**Оркестрация, контекстная память и индексирование** — файловый процесс для ИИ-агентов. Оркестровщик ведёт план и приёмку, исполнитель выполняет ограниченное задание, консультант читает без изменений. Обычный цикл: план → назначение → выполнение → проверка → приёмка → интеграция. Память и карта кода направляют новый чат к нужным фактам и коду, но не восстанавливают несохранённый разговор.

ОКПИ не является сервером, менеджером доверия клиента или автоматическим сканером проектов. Письменные правила не дают технического доступа. См.
