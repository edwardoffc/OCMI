# OCMI

[English](README.md) · **Русский**

**Orchestration, Context Memory & Indexing** — файловый рабочий процесс для ИИ-агентов.
По-русски — **ОКПИ: оркестрация, контекстная память и индексация**.

OCMI помогает вести проект в нескольких чатах и продолжать работу в новых:
роли, решения, задания и следующий шаг сохраняются рядом с проектом в Markdown.
Карта кода направляет агента к нужной области, а карточка задачи связывает требования,
результат и проверку.

## Как это работает

| Роль | Ответственность |
| --- | --- |
| Оркестровщик | Ведёт план, готовит задания и приёмочные проверки, проводит ревью и интеграцию |
| Исполнитель | Выполняет назначенную задачу в согласованных границах, проверяет результат и сохраняет отчёт |
| Консультант | Изучает проект и отвечает на вопросы без изменения файлов |

Цикл: **план → задание → реализация → проверка → приёмка → интеграция → обновление памяти**.
После интеграции учитываются оставшиеся изменения и временные ресурсы задачи.
Небольшая правка не требует отдельной ветки или нового чата только ради процесса.

## Быстрый старт

1. Скачайте [рабочий комплект](releases/ocmi-work-1.2.1-ru-2026-10-11.zip) и распакуйте его
   отдельно от целевого проекта либо клонируйте этот репозиторий.
2. Откройте целевой проект в ИИ-клиенте с доступом к файлам и передайте агенту:

   > Это рабочий проект. Внедри OCMI по INSTALL.md из указанного мной комплекта.
   > Сохрани существующие инструкции, документацию, текущие задачи и незавершённую работу.
   > Заполни память подтверждёнными фактами и проверь ссылки.

   Укажите фактический путь к распакованному `INSTALL.md` или `locales/ru/templates/work/INSTALL.md`.
3. Поручите главному агенту подготовить план и промпты для выбранных ролей.
   Количество чатов и модели выбираются для вашего проекта отдельно.

Установленная система самостоятельна: обычная работа не требует чтения исходного репозитория OCMI.
Инструкции для нового проекта, внедрения, обновления и продолжения — в [руководстве](locales/ru/docs/usage.md).

## Что хранится в проекте

| Файл | Назначение |
| --- | --- |
| `AGENTS.md` | Точка входа для агента и маршрут к правилам своей роли |
| `docs/memory/INDEX.md` | Навигация по памяти |
| `BRIEF.md`, `STATE.md`, `PLAN.md` в памяти | Цель, проверенное состояние и единая очередь работ |
| `docs/memory/CODEMAP.md` | Проверенные входные точки кода и связи с тестами |
| Карточка задачи и её handoff | Условия, результат, приёмка и точный следующий шаг |

В новом чате укажите папку проекта, роль и текущий handoff. Агент восстанавливает сохранённое
состояние и проверяет актуальность назначения. Например:

> Продолжи как оркестровщик. Прочитай AGENTS.md, входы своей роли и указанный handoff.
> Проверь актуальное состояние и продолжи со следующего шага.

Исполнителю также нужны текущее назначение, ревизия START и рабочая копия.
Документация для людей остаётся отдельной;
память ссылается на неё, а не дублирует целиком.

## Возможности и ограничения

OCMI — инструкции и шаблоны, а не сервер или автономный менеджер агентов.
Для установки не нужны база данных, плагины или подписка на отдельный сервис.
Клиент должен уметь читать файлы и получать инструкции; автоматическое обнаружение зависит от клиента.

Индексация здесь — поддерживаемая агентом карта кода, а не автоматический поиск по всему репозиторию.
Несохранённая переписка не восстанавливается. Правила не заменяют технические ограничения доступа.
Экономия токенов и качество восстановления ещё не измерены; выполненные проверки структуры
отделены от [сценариев оценки поведения](locales/ru/docs/evals/context-recovery.md).
