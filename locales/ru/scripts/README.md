# Проверки

check-context проверяет [контекст кода](../docs/context.md): определения/вызовы/контракты/тесты,
хеши WIP, сброс кэша, пропуски бюджета, границы и настоящий CLI/установленный комплект. Файлы
context-lib.ps1 и ocmi-context.ps1 побайтово совпадают с рабочими tools/; без сканирования и дискового кэша.

check-local-boundary требует Git: проверяет исключения Git/export, индекс, достижимую историю
и пути публичных ZIP, не читая содержимое служебной .local.

[English](../../../scripts/README.md) · **Русский**

check-onboarding проверяет маршруты знакомства/разработки, передачу установщик/координатор и границы
доступа на обоих языках, негативные мутации текста, небезопасные/отсутствующие входы,
версии/лицензии координатора и точные байты исходников/ZIP. Это не запуск модели.
check-release и check-onboarding используют единый текущий receipt шести профилей; default или -Version 1.3.4 выбирает OCMI 1.3.4;
-Version 1.3.0 или 1.3.1 с -ArchivesOnly проверяет исторические архивы координатора.
Промпт проверяется на шесть полей, включая ожидаемые проект клиента/привязку.

Из корня репозитория:

~~~powershell
pwsh -NoProfile -File scripts/check-all.ps1
~~~

check-docs проверяет локальные Markdown-ссылки, шесть полных/коротких схем карточек и SHA256 архивов
в обоих языковых комплектах. Внешние URL и якоря заголовков не проверяются.

check-workflow проверяет маршруты ролей, локальность входов, ограничения полномочий,
cleanup, схему карточки и отрицательные изменения текста на обоих языках.
Английские процедуры памяти разработки должны совпадать с каноническими шаблонами.
Модели и уборка не запускаются. [Поведенческие сценарии](../docs/evals/context-recovery.md) оцениваются отдельно.

check-doctor проверяет необязательный [CLI диагностики](../docs/doctor.md): явные корень/профиль,
ограниченные входы, блоки первичных записей, зависимости/ресурсы/защищённые файлы, коды выхода
и сохранность файлов. Входит в check-all Windows/macOS; установленные проекты не читаются.

check-flow проверяет поля короткой карточки, выбор по риску, покрытие, предварительные проверки, причинный повтор, повторную доработку и проверенное продолжение на обоих языках. Мутации полей/схемы/правил должны отклоняться. Это регрессия инструкций, не запуск агентов или измерение затрат.

check-localization проверяет полный состав переводов, проверенные хеши, стабильность путей
комплектов и копии лицензии. Хеши выявляют устаревание; смысл проверяется человеком.
Manifest обновляется явно после ревью, а не при запуске проверки.

check-release сверяет исходники каждого языка, receipt, точный состав ZIP, размеры и SHA256,
а также неизменность исторических архивов.
Для исторических receipts: -Version 1.2 -ArchivesOnly или -Version 1.2.1 -ArchivesOnly.
ArchivesOnly сверяет ZIP и receipt без требования исторических исходников в templates/.

Для проверок исходника требуются Git, PowerShell 7 и поддержка ZIP в .NET на Windows/macOS. Совместимость с Windows PowerShell 5.1 проверяется отдельно.
Production build, GitHub и ИИ-клиент не нужны. [Процедура выпуска](../docs/maintaining.md).

check-all запускает весь набор и проверку пробелов. check-platform проверяет системные разделители,
регистр границ Unix, пробелы/Unicode, отклонение симлинков, ограниченную уборку и реально скопированные
проверки документации/локализации. check-boundaries проверяет исключения Git/export и отклоняет шесть
искусственных мутаций индекса/истории/ZIP. Примеры не содержат данных пользователя и удаляются после
проверки границ уборки. Отдельные проверки принимают -Root; скрипты не устанавливают PowerShell
и не меняют настройки клиента. [Инструкции Windows/macOS](../docs/platforms.md).

## Проверки безопасности

check-skills сверяет каталоги/метаданные навыков en/ru, выбор по потребности/намерению/назначенным ID,
чтение только метаданных и отказ при неверном/избыточном выборе. skill-lib.ps1 предоставляет
необязательный Get-OCMISkillSelection для точного корня рабочего профиля; без загрузки тел, запуска
агентов и подтверждения готовности. Установленное [руководство](../templates/work/docs/guides/skills.md)
работает без этого помощника базы.

Перед публикацией запускайте scripts/check-security.ps1 -GitleaksPath <проверенный-нативный-gitleaks>.
Проверяются tracked-файлы и доступная история HEAD; каждый ZIP распаковывается явно.
Небезопасные пути/символьные ссылки архивов и tracked-пути резервов/ключей запрещены;
домашние идентификаторы и почта вне noreply/example требуют проверки.
Gitleaks использует встроенные правила без списков исключений репозитория и скрывает значения в выводе.
CI загружает нативные бинарники Gitleaks 8.30.1 для Windows x64/macOS ARM64/macOS x64 из официального выпуска, сверяет закреплённый SHA256 и архитектуру раннера и запускает матрицы документации/приватности. Постоянные итоговые Documentation и Secrets and privacy требуют успеха всех платформ.
Checkout закреплён commit, учётные данные не сохраняются, токены только на чтение, секреты PR не передаются.
Превышение лимита останавливает проверку. Удаляется только временный каталог, созданный этим запуском.

Default и -Version 1.3.4 проверяют все профили OCMI 1.3.4. Для исторической 1.3.3: -Version 1.3.3 -ArchivesOnly. check-versioning отклоняет разные версии компонентов и отдельные счётчики. Исходные комплекты 1.3.3: -Version 1.3.3 -LegacyComponents -ArchivesOnly; более ранние receipts используют свой номер с -ArchivesOnly.
Старый security-validation.json проверяется только как история: -SecurityBaseline -ArchivesOnly.
Проверки входа INSTALL и нейтрального правила входят в check-onboarding на обоих языках.
