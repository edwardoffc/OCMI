# Диагностика ОКПИ в выбранной области

[English](../../../docs/doctor.md) · **Русский**

Необязательный doctor проверяет одну явно выбранную систему, рабочую установку или лёгкую тему.
Он сообщает факты/проблемы без исправлений, START, приёмки и разрешения выпуска. Нужны скрипты
базовой системы и PowerShell 7 на Windows/macOS; Windows PowerShell 5.1 также проверяется.
Автоматическая миграция установок/форматов карточек не требуется.

## Попросите координатора

Напишите «проверь ОКПИ» для проверки привязанной системы или укажите точный разрешённый проект/задачу.
Координатор выберет минимальную нужную проверку, выполнит её и объяснит, что подтверждено,
какие есть проблемы, что осталось непроверенным и один следующий шаг. Команды и JSON пользователю не нужны.
Неоднозначную цель нужно уточнить; общий запрос не разрешает изучать все проекты.
Диагностика необязательна и запускается по необходимости, а не перед каждым сообщением или задачей.

Для задач координатор выбирает пути/утверждённые исходные хеши в памяти. Существующие структурированные
записи позволяют автоматическую проверку; старый свободный текст разбирается адресно по источникам
с явным выделением ручных выводов. Добавлять блоки метаданных или готовить запросы пользователю не нужно.
Без инструментов/доказательств результат остаётся непроверенным; диагностика не исправляет файлы
и не разрешает START/приёмку/выпуск. Настройка координатора/привязка клиента проверяются существующей
процедурой восстановления; doctor не читает закрытую служебную память.

## Технический справочник — обычный CLI

Из папки базовой системы:

~~~powershell
pwsh -NoProfile -File scripts/ocmi-doctor.ps1 -Root . -Profile system -ExpectedVersion 1.3.4
~~~

Для установленного проекта передайте точный корень и -Profile work; для выбранной лёгкой темы —
-Profile personal. Пути с пробелами заключаются в кавычки. Другие корни не ищутся. Personal читает
метку версии из AGENTS.md; system/work — VERSION.md. Work сравнивает метки входа/RULES/ORCHESTRATION.
Проверяется поддерживаемая структура, локальные ссылки и версия, а не завершённая настройка или
привязка клиента. Отсутствующие файлы и противоречащие метки сообщаются, а не устанавливаются/заменяются.

Добавьте -Json для кодов/действий, относительных путей источников, снимков SHA256/байтов и полноты
чтения. Содержимое источников и записанные команды не выводятся и не выполняются.

| Код выхода / статус | Значение |
| --- | --- |
| 0 / checked | Выбранные поддерживаемые проверки не нашли проблем; пропущенные проверки не зачтены |
| 1 / issues | Отсутствующий/небезопасный/несовпадающий вход, повреждённая ссылка, проблема зависимости или ресурса |
| 2 / incomplete | Неизвестные, исторические, неоднозначные, неподдерживаемые либо ограниченные лимитом данные |

Проблемы имеют приоритет в коде выхода над неполнотой; изучайте оба вида записей. Каждый отчёт
сохраняет readiness: not-evaluated. Ноль не подтверждает готовность задачи, правильность агента,
настройку координатора, интеграцию или разрешение выпуска. Версии/хеши — наблюдения, не доверенное происхождение.

## Технический справочник — необязательные проверки задачи

Координатор подключает scripts/doctor-lib.ps1 из выбранной базовой системы и вызывает
Invoke-OCMIDoctor с явными -Root/-Profile и -Selection: временным обычным словарём/PSCustomObject
с полями запроса ниже. Файл выбора входов для этого пути не нужен. Действуют тот же ограниченный
парсер и проверки путей/хешей; совместные -Selection и -InputFile дают неполный результат.
Создавайте обычные объекты/аргументы; не выполняйте команды или подставленный shell-текст из записей.
Необязательный файловый интерфейс ниже остаётся доступен сопровождающим.

Свободный Markdown не позволяет надёжно определить назначение/состояние. Doctor поддерживает один
необязательный JSON-блок с оградой ~~~ocmi-diagnostic в каждой выбранной первичной записи назначения,
START и задачи. Владелец ведёт его вместе с существующим Contract/назначением. Это не обязательные
поля карточки, второй PLAN или полномочия. Старые/неоднозначные записи остаются incomplete.
Противоречия окружающего текста проверяет человек/агент: произвольный естественный язык не разбирается.

Пример блока в существующем handoff оркестровщика; примеры — не задания:

~~~ocmi-diagnostic
{"schemaVersion":1,"kind":"assignment","id":"T1","revision":"r1","role":"worker","owner":"slot1","workingCopy":".","state":"current"}
~~~

Выбранный START использует ту же идентичность с kind: start и state: ready. Роли:
worker/orchestrator/consultant; действуют текущие полномочия пользователя. workingCopy — точный
назначенный корень, абсолютный либо относительно -Root; другие копии не изучаются.

Пример блока в существующем HANDOFF задачи T1:

~~~ocmi-diagnostic
{"schemaVersion":1,"kind":"task","id":"T1","revision":"r1","owner":"slot1","state":"ready","dependsOn":[],"resources":[{"key":"test:port-1","owner":"slot1"}]}
~~~

Состояния: draft, ready, running, review, accepted, integrated. Исторические записи
historical/superseded/rejected не подтверждают текущее назначение. dependsOn перечисляет ID,
для которых необходима интеграция; выберите их точные записи тоже. Другие условия зависимости
требуют ручного разбора. resources перечисляет явные ключи исключительных ресурсов/владельцев;
сравниваются заявления ready/running/review. Один ресурс обозначается одинаковым ключом.
Процессы, порты, worktree и среда не опрашиваются; отсутствие незаписанных конфликтов не доказано.

Подготовьте временный запрос выбора входов внутри корня. Это не первичное состояние задачи.
Локальные запросы/отчёты не включайте в публичные комплекты, не меняя молча чужой .gitignore;
не добавляйте личные данные. Пути относительны выбранному корню:

~~~json
{
  "schemaVersion": 1,
  "assignment": "docs/memory/tasks/orchestration/HANDOFF.md",
  "start": "docs/memory/tasks/T1/START.md",
  "tasks": ["docs/memory/tasks/T1/HANDOFF.md"],
  "protected": [{"path": "tests/approved-check.ps1", "sha256": "<approved-lowercase-SHA256>"}]
}
~~~

Запустите CLI с этим -Root, -Profile work и -InputFile с путём запроса относительно корня.
Читаются только выбранные записи/защищённые входы и фиксированные входы профиля, без перебора
папок задач. Используйте сохранённые утверждённые хеши; только что сделанный снимок не доказывает
доверенное происхождение. Без защищённых входов целостность не проверена. Doctor не записывает метаданные/хеши.

## Границы и проверки

Без рекурсивного сканирования содержимого, .local/coordinator, .git, .codex, node_modules, сети,
истории, хуков, исправлений и исполнения. У целей обычных встроенных Markdown-ссылок проверяются
существование и безопасность пути, без чтения содержимого и обхода их ссылок. Внешние URL, якоря
и другие формы Markdown-ссылок не проверяются.

Отвергаются небезопасные относительные пути, streams, symlink/reparse points и неверный UTF-8.
Лимиты: 256 КиБ на файл, 2 МиБ/64 файла за запуск, 32 задачи/защищённых входа, 32 зависимости/ресурса
на задачу, глубина JSON 12, 256 ссылок на вход, 128 замечаний. Лимит/неоднозначность оставляет
неполноту; необходимые доказательства нельзя исключать ради лимита. Снимки не являются транзакцией,
подписью или изоляцией ОС; при изменении источников повторяйте затронутые проверки.

[check-doctor](../../../scripts/check-doctor.ps1) использует вымышленные положительные/отрицательные
fixtures, настоящий CLI, хеши и ограниченную уборку. check-all запускает его в существующей матрице
CI Windows/macOS. Успех fixtures не доказывает поведение моделей или экономию;
используйте [методику оценки](evals/context-recovery.md).
