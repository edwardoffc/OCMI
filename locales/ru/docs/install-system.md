# Установка ОКПИ

[English](../../../docs/install-system.md) · [Русский](install-system.md)

## Канонический маршрут установки

1. Получите или переиспользуйте проверенный подходящий ReadyKit. Ссылка или
   скачанный исходный код служит для знакомства и получения подходящего
   комплекта, но не является установленной папкой исходников.
2. Проверьте контрольную сумму по доверенной записи архива, затем распакуйте комплект в новую пустую
   выбранную папку установки. Публичная часть находится в `system/`, а
   единственный исполняемый файл — `system/bin/ocmi[.exe]`. Не изменяйте
   занятую, неизвестную или частично подготовленную папку.
3. Выполните `ocmi install --home ABS` (либо проверку без записи
   `ocmi install --home ABS --inspect`). Команда создаёт только объявленную
   машинную инфраструктуру в `local/` и корень `OCMI_Sync`.
4. Координатор установки выполняет `ocmi coordinator prepare --home ABS
   --language en|ru --client-project NAME`. Команда создаёт
   `local/bindings/coordinator/STARTUP.md` и плоские переносимые файлы
   `OCMI_Sync/coordinator/{coordinator.json,AGENTS.md,INDEX.md,HANDOFF.md}`.
5. Пользователь создаёт или переиспользует проект клиента, привязанный к этой
   папке, открывает отдельный чат координатора и отправляет сгенерированный
   стартовый промпт.
6. Координатор читает плоские файлы и локальную привязку, проверяет текущую
   связь проекта инструментами или текущим подтверждением пользователя, затем
   записывает явные локальные сведения через `ocmi coordinator confirm --home ABS
   --client-project NAME --evidence-source user-current|client-tool --evidence TEXT`.
   `ocmi coordinator inspect --home ABS` только читает.
7. Только после подтверждения передачи роли координатор предлагает личное
   хранилище или внедрение в проект; ничего из этого не создаётся автоматически.

Команда записывает сообщённые сведения, но не доказывает сама личность чата
или интерфейс клиента. Не копируйте в новую папку старое доверие клиента,
базу данных, квитанцию, стартовый промпт или подтверждение. Действующие прежние
установки сохраняются как входы совместимости; перенос выполняется только
отдельно выбранным маршрутом. Никогда не публикуйте архив установленной папки.

## Обновление установленной папки

Для обновления одной явно выбранной папки используйте проверенную внешнюю
кандидатную программу. Процесс обновления работает вне целевой папки из
отдельно проверенного ReadyKit, а при активации устанавливает в неё проверенную
публичную часть. Во всех командах ниже `ocmi` означает этот внешний кандидат,
а не старый исполняемый файл выбранной папки. Сначала выполните проверку без
записи:

```text
ocmi update inspect --home ABS [--candidate ABS]
```

Применяйте обновление, только если проверка сообщает поддерживаемый переход
идентичности и известны точные ожидаемые коммиты исходной и кандидатной версий:

```text
ocmi update apply --home ABS --candidate ABS --expected-source HEX40 --expected-candidate HEX40
```

Обновление принимает только объявленные совместимые форматы из
`build-info.updateCompatibility` (схема, структура, квитанция установки,
память и привязка координатора, схема состояния). Это не произвольный перенос
данных, замена checkout исходников, загрузка/сборка или восстановление всей
папки. Старый, будущий или иной неподдерживаемый формат обязан отказаться до
активации.

Поддерживаемый переход сохраняет постоянные пути и идентичность выбранной
папки: `OCMI_Sync`, `local`, привязки, кэш, запуски, идентификаторы, связь с
проектом клиента, язык, данные жизненного цикла/свидетельств и ресурсы STOP
остаются состоянием, а не содержимым обновления. Меняются только публичная
система и объявленные квитанции исходника либо сгенерированный вход STARTUP
координатора после проверки ожидаемого промпта. Обновление не перезагружает
работающий процесс автоматически; перезапускайте или открывайте клиент только
обычным разрешённым пользователем способом. Если активации мешает занятый
исполняемый файл или нативная работа, остановите их перед повторной попыткой
только обычным разрешённым способом; не удаляйте и не заменяйте занятый файл
принудительно.

Если активация прервалась, проверка сообщает ожидающее восстановление и
следующее действие. Используйте `ocmi update recover --home ABS` только для
такой относимой незавершённой активации. `ocmi update rollback --home ABS`
допустима только при наличии последней сохранённой проверенной прежней
публичной генерации. Обе команды сохраняют это же состояние; они не создают
перенос прежней схемы и не меняют сведения о доверии или привязке.

Отказ восстановления из-за provenance содержит ограниченную `diagnostic`:
исходную границу, валидатор, неудавшуюся проверку, категорию ошибки, фазу и шаг
восстановления; ошибка ввода-вывода может включать числовой код ОС. Поля содержат
фиксированные метки и счётчики. Сохраните первый ответ и состояние обновления
для разбора: граница различает проверки до допуска и ошибки во время восстановления.
