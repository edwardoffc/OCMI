# ОКПИ на новом устройстве

[English](../../../docs/new-device.md) · [Русский](new-device.md)

Установи готовый комплект, восстанови только выбранную память, затем подтверди новые привязки клиента.
Windows, macOS и Linux используют одинаковую последовательность. Команды готовит координатор;
пользователь не пишет JSON. Этот сценарий исходной предварительной версии имеет отдельные проверки
пакетов и файлового восстановления; полная репетиция задачи на чистом устройстве и номерной публичный
релиз проходят свои этапы приёмки.

## 1. Разместить систему

Выбери архив для устройства: `windows-amd64` для Windows x64, `darwin-arm64` для Apple Silicon,
`darwin-amd64` для Intel Mac или `linux-amd64` для Linux x64. Сверь контрольную сумму с доверенной
записью издателя и точную идентичность исходников. Сумма внутри самого архива не подтверждает подлинность.
Распакуй в пустую выбранную папку системы, например `00_OCMI`. Сохрани существующие копии и WIP.

Готовый комплект содержит публичную систему, обе языковые версии, `build-info.json`, контрольные суммы,
проверенные уведомления о лицензиях и `bin/ocmi.exe` (Windows) либо исполняемый `bin/ocmi` (Unix).
Ядро запускается напрямую: для его вызова не нужны компилятор, Git, Python или PowerShell. Проверки
сопровождения системы и инструменты конкретного проекта имеют свои требования. Архив исходников или
шаблонов отличается: проверь подходящий готовый исполняемый файл, прежде чем считать ядро установленным.
Учитывай проверки скачанных программ операционной системой; не отключай защиту ради успешного теста.

## 2. Восстановить память координатора

Укажи временному установочному чату точный выбранный полный приватный снимок:

> Восстанови ОКПИ на этом устройстве из `<снимок координатора>`, используя эту папку системы.
> Восстанови только служебную память. Сохрани историю и неразрешённые операции. Покажи недостающие
> данные и шаги настройки клиента. Личные темы и рабочие проекты пока не выбраны.

Установщик читает [BOOTSTRAP](../BOOTSTRAP.md) и эту выбранную процедуру. До записи он проверяет комплект,
схему и вид снимка, совместимость исходников/версии и точное назначение. Указанная версия или хеш не
заменяют доверие. Неизвестная совместимость или миграция остаётся ожидающей. Используй существующие
[проверку и восстановление снимка](runtime-checkpoints.md) через готовое ядро из комплекта.
Восстанови в пустую `.local/coordinator`, сохранив все выбранные оригиналы и точку продолжения.
Не заменяй существующую память пустыми шаблонами и не перезаписывай конфликтующее назначение.

Сохрани старый заполненный STARTUP и текущий снимок состояния в приватной истории. Подготовь новый
STARTUP из существующего [шаблона](../templates/coordinator/STARTUP.md) выбранного языка: все шесть полей
должны содержать реальные пути системы/памяти этого устройства, идентичность исходника, языки и намеченный
проект клиента. Обнови только текущие факты о путях/привязках; сохрани решения, STOP, недостающие данные
и неизвестные операции. Старые пути, указатели проектов, PID, аренды и согласования не становятся новыми
полномочиями. Не запускай сохранённый START и не подключай аккаунты только по упоминанию в снимке.

## 3. Подтвердить проект и координатора

Создай или используй локальный проект OCMI, привяжи точную установленную папку системы как основную,
открой внутри отдельный чат координатора, предоставь необходимый доступ и отправь новый заполненный
промпт. Координатор проверит файлы, исходники, фактическую связь проекта с папкой и доступ, затем
запишет передачу роли в приватный HANDOFF. Нужны текущие инструменты или текущее подтверждение
пользователя; старые записи клиента и восстановленные файлы сами по себе оставляют настройку ожидающей.
История старого чата не требуется.

Проекты Codex организуют контекст папок; фактический доступ управляется отдельно. Конфигурация проекта,
MCP и хуки требуют поддерживаемых текущих действий по настройке и доверию. Не восстанавливай глобальную
конфигурацию клиента, авторизацию и доверие к хукам из обычных снимков памяти. Официальные инструкции:
[проекты](https://learn.chatgpt.com/docs/projects?surface=app),
[MCP](https://learn.chatgpt.com/docs/extend/mcp),
[конфигурация](https://learn.chatgpt.com/docs/config-file/config-basic).
[Руководство ядра](runtime.md) описывает поддерживаемые транспорты и их ограничения.
После файлового восстановления `readyToResume=false`, пока не завершены проверки задачи, окружения и привязок.

## 4. Продолжить выбранную тему или проект

Личная память необязательна. Для выбранной файловой темы полностью загрузи её файлы/снимок локально,
разреши конфликты синхронизации и привяжи отдельный проект клиента к папке этой темы. Новый чат читает
её собственный вход, факты и handoff. Используй [восстановление темы](personal-memory.md); не открывай
все темы и не создавай рабочую БД задач для обычного разговора. Существующие внешние хранилища
остаются на месте до отдельно выбранного переноса.

Для выбранного рабочего проекта отдельно восстанови репозиторий и необходимое продолжение Git/non-Git,
затем используй его собственное руководство настройки и [диагностику окружения](runtime-environment.md).
GitHub возвращает только отправленную работу. Доказательства, данные, секреты и доступ могут требовать
отдельно разрешённого источника. Реестр координатора — навигация, а не право читать или обновлять проект.

## Приватный транспорт

Активная служебная память находится в `.local/coordinator`; записи конкретного устройства при
необходимости — в `.local/device`. Необязательная `.local/sync/personal` содержит выбранные темы,
а `.local/sync/coordinator` — закрытые снимки координатора, не вторую редактируемую память службы.
Также подходит явно выбранная внешняя папка транспорта. Публичные комплекты не содержат этих областей.
Синхронизируй только выбранный приватный транспорт; исключи живые БД/WAL, кэши, исполняемые файлы,
учётные данные и активное состояние устройства. До проверки полностью загрузи облачные плейсхолдеры.
Сохраняй обе стороны конфликта и независимую восстанавливаемую резервную копию: синхронизация не равна
бэкапу. Установка комплекта не настраивает облачный сервис и не создаёт личное хранилище.

Попроси координатора назвать восстановленную область, сохранённые оригиналы, недостающие/конфликтующие/
непроверенные элементы, состояние привязки и одно следующее действие. При конкретном недостающем входе
или полномочии сохрани WIP и продолжи по файлам после устранения причины.
