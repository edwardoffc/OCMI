# Предварительная версия runtime OCMI

Это локальная техническая предварительная версия runtime OCMI. Она не является
выпущенной системой, миграцией установленного проекта или обещанием интеграции
с клиентом. До совместной проверки runtime, уведомлений и платформенных
проверок используйте её только с новым синтетическим корнем.

## Использование проверенного preview-архива

Запросите у координатора проверенный архив для вашей операционной системы.
Координатор проверяет его SHA256, манифесты и notices до использования. Не
собирайте runtime лишь для начала синтетической задачи. После такого результата
распакуйте архив в новую папку платформы внутри локальной системы OCMI,
например `.local/bin/<preview-id>/<platform>/`. Не заменяйте существующую папку
preview, прежний исполняемый файл или папку проекта. Пакет для другой ОС не
является свидетельством пригодности для этой ОС. Для Windows используется ZIP,
а для macOS и Linux — `.tar.gz`, в котором файл `ocmi` помечен исполняемым
через проверенный маршрут установки координатора.

Для первой синтетической задачи создайте новую пустую тестовую папку и
отправьте координатору этот ограниченный запрос, заменив только путь и
вымышленную задачу:

> Используй preview runtime OCMI только для `<абсолютный синтетический корень>`.
> Явно привяжи этот корень, покажи его текущий status и идентификаторы, затем
> подготовь одну вымышленную задачу. До любой значимой операции сообщи
> привязанные входы, проверки, команду и владельца. Не читай и не
> инициализируй другие проекты.

Координатор должен вернуть выбранный корень, привязку/идентичность, текущее
состояние и следующее разрешённое действие. Отсутствующее состояние,
неизвестная операция или недоступный вход требуют остановки и сохранения
свидетельств, а не предположения или повтора.

Для продолжения после прерывания используйте тот же явный корень:

> Продолжи выбранный preview-корень OCMI `<абсолютный синтетический корень>`.
> Проверь status и сохрани последний ответ. Если операция неизвестна или не
> завершена, назови нужные свидетельства и сверку; не запускай её повторно.

Для другого устройства не копируйте SQLite-базу или её WAL. Сохраните корень
источника и попросите координатора подготовить выбранную передачу, проверить
привязку назначения и сообщить о конфликтах или интервале недоступности
источника. Тайм-аут, скопированный бинарный файл, старый чат или транскрипт не
переносят полномочия автоматически.

## Справка оператора и разработчика

Проверка выбранных инструментов проекта и шаги восстановления со ссылками на источники описаны
в [восстановлении окружения](runtime-environment.md). Оно дополняет диагностику памяти и
[контрольные копии](runtime-checkpoints.md); проверка не запускает старую задачу и не устанавливает программы.

Кандидат исходников RESOURCE-040 содержит ограниченный учёт ресурсов; проверки компонента на
поддерживаемых ОС не подтверждают полное восстановление установленного проекта. Пользовательский
маршрут через координатора, различие ownership/use, управляемые временные группы, STOP и пределы
providers описаны в [ресурсах runtime](runtime-resources.md).

Дайте агенту один выбранный синтетический корень, задачу, исполнителя и reviewer. Агент сам ведёт
request ID, читает `status` перед каждым шагом и сообщает ответ/следующее действие: пользователю не
нужно готовить JSON. Порядок: `init` (владелец) → `task.bind` (владелец: абсолютный executable,
args, contract и inputs) → `task.ready` → `run` (исполнитель) → `submit` (исполнитель) → `review`
(другой reviewer) → `integrate` (владелец) → `resource.close` (владелец). Каждая мутация использует
revision ответа как `expectedRevision`; устаревший revision или изменённый повторный request ID
отклоняется. `status` только читает.

Предварительная версия хранит одну активную задачу и ограниченную историю задач, ревизий,
проверок и решений. Ревизия сохраняет идентификаторы задачи и результата; перед выполнением
заново проверяются готовность и входные данные. Переименование не стирает историю неудач.
Повторы не запускаются автоматически: оркестровщик проекта фиксирует изменённый подход и
основание для одной попытки. Незавершённая операция не считается успехом. Запросы и JSON ведёт агент.

Текущий кандидат исходников использует формат локального состояния и переноса v4; неизменяемый
архив core-r1 остаётся на v2 и не заменяется обновлением исходников. В кандидате `task.bind`/
`task.revise` требуют `completionScope: "target"|"preparation"`. Приёмка подготовки сохраняет
ограничения повторных попыток результата и не выдаёт новых; только приёмка явного целевого
результата завершает эпизод. Признак хранится в status/history и переносе, а не выводится из текста ревью.

Владелец явно выполняет `state.upgrade {}` для выбранного состояния v1/v2 с согласованной
резервной копией, читаемой старой программой. Старые задачи получают `legacy_unknown`: их
приёмка не означает завершения целевого результата. Отсутствующее, повреждённое, неоднозначное
или более новое состояние остаётся нетронутым. Пакет v3 сохраняет ограниченный журнал, а
проверенные пакеты v1/v2 импортируются с неизвестным признаком в изолированное состояние.
Нужны локальная перепривязка команды и новые доказательства; при необходимости задайте признак
явно в новой ревизии. Для прерванной операции
`operation.inspect` и `operation.reconcile` возможны лишь при зарегистрированном владении и
проверенном отсутствии процесса. Если нет регистрации, совпадающего контекста или доказательства
отсутствия, состояние остаётся неизвестным; обход по текстовой причине и автоматический запуск невозможны.

Операторский запрос содержит `schemaVersion: 1`, явные `projectRoot`, `actor`, `requestId`,
`expectedRevision`, `action` и `payload`. Вымышленный bind включает `taskId`, `outcomeId`,
`taskRevision`, `completionScope`, `worker`, `reviewer`, относительные `contract`/`inputs` и `command` с абсолютным
`executable`, `args`, относительным `cwd`, timeout и output limit. Worker и reviewer не совпадают.

| Action | Payload |
| --- | --- |
| `init` | `{ "projectId", "deviceId", "copyId", "owner" }` |
| `task.bind` | `{ "taskId", "outcomeId", "taskRevision", "completionScope", "worker", "reviewer", "contract", "inputs", "command": { "id", "executable", "args", "cwd", "timeoutMs", "outputLimitBytes" } }` |
| `task.ready`, `run`, `submit`, `status` | `{}` |
| `stop` | `{ "enabled": true|false }` |
| `review` | `{ "accept": true|false, "reason" }` |
| `integrate` | `{ "candidate", "reason" }` |
| `resource.close` | `{ "disposition": "keep"|"remove"|"transfer", "reason" }` |
| `handover.rebind` | `{ "command": { "id", "executable", "args", "cwd", "timeoutMs", "outputLimitBytes" } }` |
| `task.revise` | Полный текущий bind payload плюс `{ "reason" }` |
| `task.history`, `state.upgrade` | `{}` (history может выбрать task и limit) |
| `operation.inspect` | `{ "operationId" }` |
| `operation.reconcile` | `{ "operationId", "disposition": "abandon", "reason" }` |
| `outcome.reassess`, `outcome.review`, `outcome.decide` | Ограниченное owner judgment для `outcomeId`; evidence и grant проверяет core |

### Передача выбранного корня

Экспортируйте contract и каждый required input: `{ "transferId": "fictional-x", "files": ["contract.md", "input.txt"] }`.
Он возвращает JSON с checksum; копируйте только его, никогда не SQLite/WAL. Импортируйте
`{ "package": <exported package>, "deviceId": "fictional-device", "copyId": "fictional-copy" }`
только в явно выбранный **пустой** корень. Лимиты: 32 файла, 1 MiB на файл, 4 MiB raw и 8 MiB
кодированного запроса. История сохраняется, raw operation output опущен и отмечен. Назначение
получает STOP/draft: снимите STOP, вызовите `handover.rebind` с локальной командой и выполните
свежий запуск до submit. Ack: `{ "transferId": "fictional-x", "generation": <export generation> }`.
Export замораживает источник; cancel в preview отклонён, поскольку offline-пакет нельзя отозвать.
Недоступный источник оставляет ownership неразрешённым.

Начальный CLI принимает один JSON-запрос через стандартный ввод. Это интерфейс
оператора, а не путь пользователя к первой задаче:

```powershell
Get-Content C:\path\to\runtime\examples\init-request.json -Raw |
  & C:\path\to\ocmi.exe request
```

Пример намеренно вымышлен. В нём указан явный корень и владелец; это не команда
для инициализации существующего проекта.

Для проверенной preview-версии с MCP-адаптером запустите ограниченный stdio
сервер с явным корнем и исполнителем:

```powershell
& C:\path\to\ocmi.exe mcp --project-root C:\ocmi-preview-synthetic --actor preview-owner
```

Он не обнаруживает и не инициализирует другой проект. После выбора сервера
дайте агенту такой стартовый prompt:

> Используй preview runtime OCMI только для `C:\ocmi-preview-synthetic`.
> Сначала проверь выбранный status и привязку. Подготовь одну вымышленную
> задачу и до любой значимой операции покажи её входы, проверки, команду,
> владельца и следующее разрешённое действие.

Наличие адаптера не доказывает доверие к hook, настройку клиента или широкое
принуждение инструментов.

Собирайте предварительную версию только из проверенной рабочей копии. Сборщик
создаёт новую уникальную папку в `.local/development/runtime-043/distributions`;
он не обновляет номерной релиз OCMI и не изменяет существующий дистрибутив.
Нужны уже установленный Go 1.26.2, кэш закреплённых модулей и проверенный
манифест уведомлений. Сборщик не устанавливает Go, не загружает зависимости,
не настраивает клиент и не использует старый бинарный файл.

```powershell
pwsh -NoProfile -File scripts/build-runtime-preview.ps1 `
  -NoticesManifest C:\reviewed-notices\notices.json
```

Манифест — это JSON рядом с проверенными файлами уведомлений. `notice` —
относительный путь от папки манифеста, а каждый digest — SHA256 в нижнем
регистре. Список модулей должен точно совпадать с нестандартными модулями,
входящими в выбранный бинарный файл; показанная структура неполна:

```json
{
  "schemaVersion": 1,
  "toolchain": {
    "version": "go1.26.2",
    "notice": "go/LICENSE",
    "sha256": "<64 lowercase hexadecimal characters>"
  },
  "modules": [
    {
      "path": "modernc.org/sqlite",
      "version": "v1.61.1",
      "notice": "modules/modernc.org/sqlite/LICENSE",
      "sha256": "<64 lowercase hexadecimal characters>"
    }
  ]
}
```

Сборщик использует `go build -trimpath` с отключённым CGO для Windows amd64,
macOS arm64/amd64 и Linux amd64. Он записывает граф модулей и никогда не
использует старый бинарный файл. Отсутствующее, устаревшее, дублирующееся или
нечитаемое уведомление останавливает упаковку. Кросс-компиляция показывает
только факт сборки цели, а не нативное выполнение на этой ОС. Windows
упаковывается как ZIP; macOS и Linux — как `.tar.gz` с mode `0755` для `ocmi`
и mode `0644` для всех остальных включённых файлов. `build-info.json` хранит
отсортированный SHA256-снимок только с относительными путями исходников Go в
`runtime`, `go.mod` и `go.sum`; при изменении такого снимка во время сборки
упаковка отменяется.

Перед реальной сборкой выполните контролируемую проверку staging:

```powershell
pwsh -NoProfile -File scripts/build-runtime-preview.ps1 -SelfTest
```

Она проверяет границу упаковки на временных вымышленных файлах. Runtime при
этом не собирается, а пригодность пакета не доказывается.

## Продолжение и сбой

Для просмотра ограниченного текущего состояния используйте `status` с тем же
явным корнем. Прерванная или недоступная операция не означает успех и не должна
запускаться вслепую повторно. Сохраните корень, созданные свидетельства и
последний ответ; выполняйте сверку только через явно поддерживаемое действие,
когда оно появится. Ненулевой выход команды, усечённый вывод, устаревший вход,
отсутствующее состояние или неизвестная операция не могут закрыть обязательную
проверку.

STOP запрещает новую значимую операцию. Сам по себе он не доказывает остановку
уже работающего дочернего процесса. Очистка, review и интеграция остаются
отдельными решениями со своими свидетельствами.

Для зарегистрированной операции в том же контексте с подтверждённым средствами ОС отсутствием
сначала выполните `operation.inspect`, затем владелец может перевести её в незавершённое состояние
через `operation.reconcile`. Запускаемая, незарегистрированная, устаревшая или неоднозначная
операция остаётся неизвестной. Автоматический повтор и сверка только по текстовой причине невозможны.
Hooks — необязательные ограниченные
guardrails; preview не заявляет, что клиент их установил, доверяет им, запускает их или охватывает
произвольные shell-команды. Native-квалификация нового runtime ещё ожидается; старый probe CI ею не
является.

## Границы устройств и личных данных

Корень предварительной версии привязан к заявленным идентификаторам проекта,
устройства, копии и исполнителя. Не копируйте между устройствами живую SQLite
базу или её WAL. Переносимость, когда она появится, должна использовать явный
экспорт/импорт; частичный, конфликтующий, повторённый или недоступный у
источника перенос остаётся неразрешённым до сверки. Сборка для другой ОС не
делает прежние свидетельства команд действительными на ней.

Необязательная раскладка личных файлов этой предварительной версией не
устанавливается:

```
.local/sync/personal/
  00-inbox/  10-projects/  20-areas/  30-resources/  40-archive/  90-system/
```

Восстановление темы по файлам требует полных локальных файлов и ограниченной
привязки клиента, а не старого чата или базы runtime. `.local/coordinator`
содержит состояние координатора, а `.local/sync/coordinator` зарезервирован для
снимков передачи; ни одно из них не входит в preview-пакет. Поставщик облака и
правила синхронизации выбираются отдельно. Конфликты, недоступные исходные
файлы, доверие к hook, перенос sidebar/чатов, поведение модели и измеренная
эффективность остаются вне гарантий этой версии.

## Обновление и сохранность

Для выбранных файлов без Git есть отдельный [компонент контрольных копий](runtime-checkpoints.md);
его область и результат `requires_rebind` ещё не означают полное восстановление проекта или устройства.

Перед новой предварительной версией сохраните прежний исполняемый файл и полный
выбранный корень. Не перезаписывайте существующую папку предварительной версии.
Предоставляйте секреты вне архива и отдельно от runtime; обычный status и
пакеты не предназначены для переноса секретов. Автоматической миграции,
настройки клиента или облака и синхронизации личного хранилища здесь нет.
