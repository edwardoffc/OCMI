# Основа структуры runtime

OCMI поддерживает два явно выбранных корня runtime: папку рабочего проекта и
папку установленной системы. Эта основа выбирает пути; она не подтверждает доверие,
происхождение пакета, готовность или завершение задачи.

Прямой JSON-запрос `ocmi request` передаёт поля `projectRoot` и `rootKind`.
При запуске MCP и hooks используются `--project-root` и, при необходимости,
`--root-kind installation`. `layout.inspect` — просмотр структуры только на
чтение: он сообщает выбранный тип корня и относительные пути. Он не создаёт
базу данных, каталоги, данные и не выдаёт роль.

Папка установленной системы уже должна содержать обычный `.ocmi-home.json`,
скопированный из [нейтрального runtime-описания](../../../runtime/internal/installation-layout.json).
В описании разрешены только такие относительные пути:

| Имя | Относительный путь |
| --- | --- |
| system | `system` |
| нативные бинарные файлы | `system/bin` |
| переносимая граница sync | `OCMI_Sync` |
| данные координатора | `OCMI_Sync/coordinator` |
| необязательные личные данные | `OCMI_Sync/personal` |
| данные восстановления | `OCMI_Sync/recovery` |
| локальные данные машины | `local` |
| state | `local/state` |
| store | `local/state/state.sqlite` |
| bindings | `local/bindings` |
| cache | `local/cache` |
| runs | `local/runs` |

Необязательный личный каталог никогда не создаётся просмотром структуры или
инициализацией. Они не сканируют, не переносят и не копируют пользовательские
данные. Установщик, обновление и перенос восстановления — отдельная поздняя
квалифицированная работа; эта основа структуры не является готовым установщиком.

Режим проекта сохраняет совместимость с существующим локальным состоянием
проекта. Запрос проекта к объявленной папке установленной системы отклоняется
вместо создания второго хранилища учёта. Запрос папки установленной системы
отклоняет отсутствующее,
некорректное, связанное, выходящее за границы или конфликтующее описание и не
возвращается неявно к режиму проекта.
В этом срезе операции `handover.*`, `state.upgrade`, `checkpoint.*` и
`environment.*` над всей папкой установленной системы не поддерживаются.
