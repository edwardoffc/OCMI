# Кандидат OCMI 2.0.0

Этот двуязычный кандидат выравнивает нативный вход проверенной папки установки
с рабочим, личным и устаревшим координаторским входами профилей. ReadyKit
остаётся единственным источником нативного пакета; ZIP профилей — входы
координатора, а не полные установки.

Текущая [квитанция комплектов](../../../../docs/releases/2.0.0-workflow-r4.json) сохраняет
исходную квитанцию и архивы. Точные необязательные ссылки на инструменты и
компактный native-маршрут описаны в установленных руководствах runtime.

После явной нативной привязки `context.inspect` может сообщать свежие
операционные факты или проверенный производный ready START. Main должен явно
передать это представление; оно не является одобрением, анализом семантических
зависимостей или заменой целого смыслового Contract и входов. Сохраняйте
один семантический PLAN, обоснование, открытые вопросы, Result и Acceptance;
не копируйте производное состояние задач или машины в Markdown после команд.

Новые нативные папки используют `OCMI_Sync/coordinator` с локальной
машинной привязкой. Восьмифайловый шаблон координатора сохранён только для
устаревшей совместимости и не является маршрутом новой нативной установки.
Личная память тем остаётся необязательными переносимыми файлами выбранной
области, обычно в `OCMI_Sync/personal`.

Это кандидат исходников, не стабильный выпуск и не приёмка пилота. Он не
заявляет универсального принуждения инструментов, измеренной экономии или
завершённой кросс-платформенной квалификации.
