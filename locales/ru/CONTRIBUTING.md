# Участие в разработке OCMI

[English](../../CONTRIBUTING.md) · **Русский**

Предлагайте изменение через Issue или Pull Request: наблюдаемая проблема,
воспроизводимый пример и ожидаемый результат. Используйте вымышленные данные;
не прикладывайте журналы чатов, секреты или документы закрытых проектов.

Общие рабочие правила меняются в `templates/work`, облегчённый профиль — в `templates/personal`.
Документация для пользователей находится в `docs`. Не переносите в общий комплект
локальные пути, полномочия, выбор моделей или текущие задачи конкретного пользователя.

Английский — основной язык исходников; русские эквиваленты находятся в locales/ru.
Обновляйте переводы по [правилам локализации](docs/localization.md).
Сохраняйте пути, ID, Contract/Result/Acceptance, ready/running/review/accepted/integrated
и cleanup: done/pending. Хеши manifest обновляйте после смыслового ревью.

Перед отправкой выполните из корня репозитория:

~~~powershell
powershell -NoProfile -File scripts/check-docs.ps1
powershell -NoProfile -File scripts/check-workflow.ps1
powershell -NoProfile -File scripts/check-localization.ps1
powershell -NoProfile -File scripts/check-release.ps1
git diff --check
~~~

Проверки рассчитаны на Windows PowerShell 5.1; шаблоны — обычные Markdown-файлы.
Структурная проверка не доказывает качество работы модели или экономию токенов.
Для изменения поведения правил укажите проверяемые сценарии и ограничения результата.

Сохранённые ZIP не перезаписываются. Если меняется содержимое шаблона, сопровождающий
готовит отдельную версию и receipt по [процедуре выпуска](docs/maintaining.md).
Локальная память установленного проекта не входит в Pull Request к OCMI.

Материалы репозитория распространяются по [MIT](../../LICENSE).

Перед публикацией запускайте проверку безопасности с проверенным сканером. Сообщайте об уязвимостях приватно по [SECURITY](SECURITY.md). Изменения входят в main через PR с Documentation и Secrets and privacy; одобрение второго сопровождающего не требуется.
