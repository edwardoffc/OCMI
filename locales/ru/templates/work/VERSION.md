# OCMI 1.2.3

**OCMI 1.2.3, редакция правил 2026-10-13**

Orchestration, Context Memory & Indexing — оркестровщик, контекстная память и индексация.
Совместимое исправление рабочего процесса профиля 1.2.2. Облегчённый профиль остаётся 1.2.1.

## Изменения относительно 1.2.2

- Короткая карточка выбирается для ограниченных, обратимых задач с низким риском; чувствительные и неопределённые задачи сохраняют полный формат.
- Достаточные существующие проверки подтверждаются до START; новые тесты закрывают пробелы. Перед дорогим CI идут подходящие дешёвые проверки.
- Доказательства падения сохраняются: успешный повтор сам по себе не объясняет сбой. Повторная доработка требует причины/гипотезы и изменённого способа диагностики.
- При проверенном контексте продолжение читает изменившиеся записи; новый чат или неопределённое состояние восстанавливает обязательные входы.

Обновление системы 1.3.3 включает этот рабочий протокол. Политика координатора/установки остаётся 1.3.2.
Выданные контракты, обязательные проектные проверки и защищённые checkers сохраняют силу.

## Изменения относительно 1.2.1

Очищай логи, общую память, fixtures и архивы до сохранения/публикации.
Для нужного оригинала требуется явно разрешённое закрытое место и владелец хранения.
Сохраняй поля задач и защищённые пакеты; раскрытие ключа требует реакции на инцидент.

## Сохранённые изменения относительно 1.2

- Один основной рабочий контекст задачи; R1/R2 используют прежнюю пригодную копию.
  Новая ветка/worktree требуется по условиям задачи, не для каждой небольшой правки.
- Временные ресурсы имеют владельца, условие завершения и судьбу; учитываются в существующей карточке.
- После интеграции главный проверяет WIP, процессы, сохранность, зависимости, полномочия и ссылки.
  Исполнитель сообщает состояние ресурсов; повторный полный прогон ради уборки не нужен.
- В Acceptance отдельный cleanup: done/pending. Ожидающая уборка не отменяет принятую реализацию,
  но не позволяет потерять остаток; причина, владелец и следующее действие сохраняются.
- Уникальные изменения и evidence сохраняются; воспроизводимые сборки/кэши не архивируются автоматически.
  Общий cache допустим; основная копия не зависит от удаляемой временной.
- Безопасный отказ удаления не разрешает force. Хеш без доступного содержимого не считается резервной копией.
  Детали завершения находятся в процедуре главного; общее чтение остаётся коротким.

## Совместимость

Сохраняются ядро/маршруты 1.2, три раздела Contract/Result/Acceptance и поля экспортёров,
защищённые тесты, fixed baseline, WIP, единое ревью, reuse и интеграция.
Выданные пакеты/checkers неизменны. Новые правила — для новых назначений/явных ревизий.
Отсутствующий cleanup старой карточки не означает done; оставшиеся ресурсы учитываются отдельно
в текущем handoff/Acceptance со ссылкой на оригинал, без переписывания защищённого пакета.
Проектные полномочия не расширяются; автоматического удаления и фоновой уборки нет.
Установленные проекты не обновляются автоматически; переход — по [INSTALL](INSTALL.md).
Номер версии, дата правил и ревизия задачи r1/r2 — разные обозначения.

Проверки структуры и архивов не доказывают поведение модели или экономию токенов.

Правила установщика: система OCMI 1.3.2. Новые установки выполняет настроенный координатор.
Рабочий протокол — 1.2.3; обновление исходника не переносит установленные проекты.
