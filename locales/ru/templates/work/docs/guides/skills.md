# Выбранные навыки и необязательные специалисты

ОКПИ 1.3.5. Навык — повторно используемая процедура внутри текущей роли, не новый агент или полномочия.
Оркестровщик читает только [метаданные каталога](../../skills/catalog.json), находит действительный пробел
и загружает нужный SKILL.md. Нет пробела — навык не нужен; обычная задача не требует новых формальностей.

| Потребность | Навык | Полезный вход → выход |
| --- | --- | --- |
| reuse | ocmi-search-first | Возможность/потребитель → существующий путь либо решение «использовать/расширить/написать» |
| diagnose | ocmi-ci-triage | Ошибка/лог/среда → причинная гипотеза, адресная диагностика и достаточные следующие проверки |
| tests | ocmi-test-design | Критерий/пробел покрытия → предложение проверки, oracle, fixture и ограничений |
| review | ocmi-review | Фиксированный Contract/diff/доказательства → одно сводное ревью поведения/качества |
| security | ocmi-security-review | Запрос безопасности или конкретный риск границы доверия → адресные замечания/пробел регрессии |

Метки намерения bug/change/research/review/release/question сужают кандидатов; одно намерение или
слово о риске не требует всех подходящих процедур. Проверки безопасности проекта продолжают действовать.
Читайте только выбранные навыки; не загружайте весь набор, чужую роль или несвязанную историю.
Укажите ID и точные пути/редакцию источника в существующих обязательных входах START. Без новых
обязательных полей, второй очереди/чек-листа или Result-файла. Исполнители читают только адресованные
выбранные входы; консультанты работают на чтение. Недостающие обязательные входы обрабатываются
по действующим правилам готовности/редакций. Навык не перечитывается при каждом подтверждённом продолжении.

## Функции специалистов

По умолчанию применяйте процедуру в текущей роли. Отдельный ограниченный вклад необязателен и
полезен при конкретном пробеле покрытия, компетенции или контекста. Постоянный чат на функцию не нужен.
Единственный оркестровщик ведёт PLAN, критерии/защищённые проверки, сводные замечания, приёмку и интеграцию.
У задачи один владелец. Без автоматического запуска, вложенных ревьюеров и смены модели.

- **Совет по тестам:** передайте критерий, потребителя, текущие проверки и пробел. Получите предложения
  тестов/fixtures и доказательства. Оркестровщик проверяет их до фиксации. Советник на чтение не пишет
  и не запускает тесты. Реальная передача написания тестов требует обычного адресованного START,
  разрешённых путей/ресурсов и проверки оркестровщиком до защиты подготовленных тестов.
- **Ограниченное ревью:** передайте фиксированную редакцию/diff, критерии, действующие доказательства
  и точный вопрос. Получите замечания на чтение в текущем обмене; оркестровщик запишет их в существующий
  Acceptance, без отдельного конкурирующего вердикта. Вне diff читать по конкретному риску.
- **Совет по CI или безопасности:** используйте соответствующий навык для названной проблемы.
  Полномочия выпуска и проверки безопасности сохраняются. Архитектура/планирование и предметные
  наборы — последующие возможности, не обязательные роли.

Реальная передача работы, чаты/сообщения/инструменты требуют действующих полномочий и возможностей.
Если их нет, используйте процедуру в текущей роли либо верните ограниченное предложение; каталог
не является причиной просить другую модель. Не подменяйте задачу исполнителя.
Для вклада укажите цель, входы/редакцию, ограничения чтения/записи/команд, место результата, условие
остановки и владельца ресурса при необходимости. Изменённое назначение/проверка фиксируется явной редакцией.

Первое сводное ревью охватывает требования и качество. После исправлений проверяйте изменения,
старые замечания и затронутые связи. Используйте действующие доказательства; дополнительные тесты/ревью
закрывают реальные пробелы. Без обязательного полного дублирующего прогона, цепочки ревьюеров и
циклов согласования. Новые критические риски остаются блокирующими.

## Работа в установленном проекте

Пользователь описывает задачу обычным языком; оркестровщик выбирает процедуры и объясняет отдельный
вклад при необходимости. Пользователь не пишет каталог/JSON, не создаёт обязательный чат и не
устанавливает нативный навык клиента. Действующая установка получает набор только явным обновлением
с сохранением локальных правил, выданной работы и WIP. Набор самодостаточен; обычная работа не читает реестр базы.

Метаданные каталога — производная навигация, не первичное состояние задачи. ID, пути, потребности
и метки намерения одинаковы между языками; описания/инструкции используют язык установки.
Необязательное обоснование связано с каждым навыком; авторский текст ОКПИ под MIT, без заимствованного кода.
Помощник выбора, если доступен, читает только метаданные и возвращает кандидатов/назначенные ID;
не читает тела, не подтверждает START и не запускает агентов. Без него каталог можно использовать напрямую.
Сравнивайте принятые результаты, возвраты и доступные затраты в существующем Acceptance; число навыков
не доказывает экономию. Скрипты/fixtures не доказывают выбор навыков живой моделью и качество специалистов.
