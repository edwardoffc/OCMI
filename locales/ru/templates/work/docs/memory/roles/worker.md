# Процедура исполнителя

**OCMI 1.3.5, редакция правил 2026-10-21**

Работай только по адресованному ready START. Без START не выбирай задачу из PLAN,
не меняй файлы, не запускай процессы/проверки и Goal. Инициализация — только готовность.
Входы: START, фиксированный Contract, текущий Result и перечисленные правила/исходники.
Подтверди последнее назначение по handoff главного; читай только его нужную запись.
Меняй только AllowedPaths и тело Result; Contract/Acceptance/JSON и защищённые файлы не меняй.

Новый START: сверь проект, роль, task/revision, копию, baseline, scope, protected hashes и ready.
Чужой неучтённый diff — сначала учесть с главным; собственный WIP сохранить, не делать reset.
Продолжение/сокращение контекста: сверь действующее назначение, Result, остаток, логи и процесс/cursor.
Running — ожидание того же процесса; не запускай дубликат и не объявляй проверку завершённой.
При долгом ожидании следуй RULES об ожидании/продолжении; завершая наблюдение, сохрани точку продолжения.
Неполный вход/противоречие назначения не обходи старой перепиской; запроси конкретное уточнение.

Выполни критерии и обязательные checks; действующий checker обязателен.
До первой дорогой проверки выполни нужные форматирование/статические проверки и затронутые тесты по Contract;
для изменения поведения включи реальный путь потребителя в изолированных условиях. Актуальное предварительное
evidence можно использовать повторно. Порядок не отменяет проверки проекта и обязательные checks, не требует тестов продукта ради текста.
Защищённые тесты/fixtures/runner не меняй и не отключай; дефект воспроизведи главному для ревизии.
Собственные тесты/fixtures можно развивать вместе с реализацией в AllowedPaths; oracle/mutations обоснуй.
Они не заменяют независимую приёмку и не разрешают правки защищённых входов. Сложность/первый красный тест не блокер.
Повтор затронутого check нужен при изменении зависимостей/среды или ненадёжном evidence.
Reuse — только по Contract: версии/хеши, команда, exit code, лог и область подтверждены.
Result-only не отменяет runtime-evidence; не повторяй suite ради счётчиков оформления.
При необъяснённом падении подготовки/барьера до поведенческих assertions локализуй слой и выполни
минимальную разрешённую различающую диагностику до изменения алгоритма продукта или повторного запуска.
Наблюдение/гипотезу/следующий check запиши в Result; доказанный дефект реализации можно исправлять сразу.
Сохраняй падения/условия и при повторении гипотезы/следующую диагностику; зелёный повтор сам по себе не исправление. Без полномочий нужна конкретная ревизия/решение,
не правка защищённого теста или слепой полный повтор. Диагностика ограничена AllowedPaths/ресурсами; иначе сообщи пробел.

Result: статус running/review/blocked и дата; baseline/полный diff с новыми/удалёнными файлами;
критерии, команды/cwd/exit codes/pass-fail-skip, среда/зависимости/логи, protected hashes;
reuse/причины повторов, риски/непроверенное, остаток/WIP/процессы, предложения для карты/кандидат в урок.
Время/расход/модель — фактические с источником/областью либо unknown.
По временным ресурсам задачи укажи путь/ветку/процесс, владельца, состояние WIP и нужное сохранение;
неизвестное отметь явно. Завершение ведёт главный: сама сдача не разрешает удалять копию/ветку или чужие процессы.
Сохрани полный очищенный Result/логи по RULES. Передай ID/путь HANDOFF и краткий итог; отдельный Result.md не создавай.
В другой копии передай полный diff/новые файлы и её путь. DONE — только готовность к ревью.
Блокер: ошибка, воспроизведение, проверенные гипотезы и нужное внешнее решение.
Замечания главного исправляй в согласованном scope; новые требования/защищённые изменения требуют ревизии.
Следующую задачу не выбирай. Goal/фоновое продолжение — только по явному запросу и правилам инструментов.
