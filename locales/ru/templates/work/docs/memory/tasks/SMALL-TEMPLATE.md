# TASK-ID: один ограниченный результат

**OCMI 1.3.4, редакция правил 2026-10-13**

Format: compact
Risk: low
Status: draft

Шаблон, не START. Использовать только после проверки низкого риска главным по
[выбору формата](../TASK-PROTOCOL.md). Один HANDOFF; защищённые поля экспортёра сохраняются, если есть.

## Contract

- Задача / ревизия / владелец / рабочая копия: точная идентичность, текущий START и пункт PLAN.
- Результат / критерий / потребитель: один наблюдаемый результат; почему ограничен, обратим и малорисковый.
- Область / AllowedPaths / baseline / WIP: нужные callers; фиксированный commit/snapshot и сохранённая работа.
- ProtectedPaths / хеши: проверки и фиксированные входы либо подтверждённое отсутствие; выданный checker обязателен.
- Проверки / evidence / достаточность: каждый критерий → существующая проверка либо тест для пробела; cwd/команды,
  среда и предварительные проверки; допустимый reuse, финальная интеграционная проверка и существенные пределы.
- Входы / полномочия / ресурсы: точные доступные входы, разрешения и зависимости; ресурсы отсутствуют
  либо указаны владелец/завершение/судьба. Неизвестный риск или пробел обязательных входов требует полного формата до START.

## Result

Исполнитель: статус/дата, diff, команды/exit codes/логи проверок либо подтверждённый reuse, риски и остаток WIP/процессов.
Сохраняй evidence падений; успешный повтор сам по себе не исправление. Contract и Acceptance не менять.

## Acceptance

Главный: единое решение/findings, принятая и интегрированная версии/evidence;
причина повторного падения/гипотеза/следующая диагностика, если нужны; cleanup: done/pending с причиной/владельцем/действием.
Время/расход — наблюдаемые либо unknown. Проверки проекта и отдельные полномочия выпуска сохраняются.
