# Установка файловой памяти

**OCMI 1.2.1, редакция правил 2026-10-11** Этот каталог — переносимый нейтральный комплект. Он не содержит сведений о пользователе или других проектах. Установку выполняет агент по запросу пользователя; программы устанавливать не требуется.

## Порядок для агента

1. Определи целевую папку, её область (рабочая / личная) и цель из текущего запроса. Целевая папка должна отличаться от папки этого комплекта. Если область или цель действительно неизвестны, уточни только недостающее. Для постоянной темы вместо конечного результата укажи, что пользователь хочет обсуждать и отслеживать.
2. Читай только этот комплект и целевую область. Общий каталог, профиль и соседние проекты не нужны. Выполни действующие инструкции целевой папки; проверь существующие `AGENTS.md`, `AGENTS.override.md`, документы и память. В Git сначала зафиксируй для себя исходное состояние изменений, чтобы сохранить чужую работу.
3. Подготовь четыре файла по таблице ниже. **Существующие файлы не перезаписывай шаблонами:** согласуй правила с действующими инструкциями и сохрани содержимое. Если уже есть рабочая система памяти, используй её пути и единственную актуальную точку входа вместо создания второй системы ради этих имён.
4. Заполни описание и первую задачу подтверждёнными сведениями. Не выдавай предполагаемую архитектуру, команды или пожелания за факты. Неизвестное отметь явно. Ссылки ведут к исходным документам; не дублируй их целиком.
5. Дополнительные файлы создавай по потребности: решения, карту кода, журнал значимой сессии. Начальная карта перечисляет проверенные входные точки и области кода для текущей задачи; не требуется читать весь репозиторий. Указывай источник и дату проверки каждой используемой области карты.
6. Проверь относительные ссылки, наличие начального handoff и то, что клиент обнаружит инструкции при открытии целевой папки. Учитывай приоритет существующего `AGENTS.override.md`. Проверка документации не требует запуска всего приложения. Не утверждай, что восстановление в новом чате проверено, если оно не выполнялось.
7. Сообщи, где находится память, как продолжить работу, что осталось неизвестным и какие проверки выполнены. Установка в одну папку не настраивает автоматически другие проекты, глобальную автопамять или файловые разрешения.

Продолжение сверяет тему/задачу/папку, источник и остаток. Историческое/отменённое отделять от текущего.
Лёгкий профиль не требует оркестратора, рабочих карточек, LESSONS или hooks.

## Минимальный состав

Пути назначения указаны относительно корня выбранного проекта или личной темы.

| Источник в комплекте | Назначение |
|---|---|
| [AGENTS.md](AGENTS.md) | `AGENTS.md` — инструкции агенту |
| [INDEX.md](memory/INDEX.md) | `memory/INDEX.md` — навигация и список задач |
| [BRIEF.md](memory/BRIEF.md) | `memory/BRIEF.md` — цель, границы, исходные сведения |
| [HANDOFF.md](memory/tasks/main/HANDOFF.md) | `memory/tasks/main/HANDOFF.md` — текущее состояние первой задачи |

`INSTALL.md` копировать в проект необязательно. Остальные файлы образуют самостоятельную систему без ссылки на исходное хранилище настройки.

## Внедрение в существующий проект

- Сохрани документацию для людей и незакоммиченные изменения. Память ссылается на документацию, а не становится её конкурирующей копией. Дальнейшая разработка может требовать обычного обновления документации.
- Найди существующие заметки ИИ в пределах проекта. Если пользователь говорит о другой папке, но путь неизвестен, запроси его; не сканируй весь диск.
- Составь `memory/MIGRATION.md`: старый источник → новое место или ссылка → что проверено → что осталось перенести. Сохраняй происхождение важных решений. Отделяй исторические сведения от актуальных.
- Оставь оригиналы доступными на время проверки миграции. Старые точки входа должны явно указывать на единственное актуальное состояние. Не удаляй источники только потому, что появился новый handoff.
- Если уже используется GSD, Serena или другой процесс, расширяй его действующую память и навигацию. Не создавай два независимо обновляемых описания текущего состояния.

## Другие клиенты и границы доступа

Клиент должен получать инструкции в поддерживаемом им формате. Для Codex используется `AGENTS.md`; обнаружение зависит от корня проекта и текущей папки. В Claude Code можно добавить в `CLAUDE.md` документированный импорт `@AGENTS.md`, сохранив один источник правил. Для других клиентов проверь их актуальную документацию.

Разделение папок и инструкции управляют выбором контекста, но не устанавливают права доступа. Если нужна техническая изоляция, отдельно настрой ограничения среды, подключённых источников и общей автоматической памяти. Проверяй настройки, не открывая для проверки чужие личные материалы.

Если агент не может читать или изменять файлы, передай ему индекс, описание и нужный handoff вручную; обновлённые файлы сохрани обратно. Не называй такой обмен автоматической установкой на диск.
