# Повседневная память темы

Читай только нужный сценарий. Обычное обсуждение не требует рабочего оркестровщика, START, матрицы
задач, протокола всей переписки или повторной установки. Текущим источником остаётся память темы.

## Новая или неопределившаяся тема

После подтверждённой базовой установки попроси координатора создать выбранную тему в согласованной папке.
Для неопределившегося предмета можно использовать `inbox/<stable-topic-id>/`, для определившегося —
`topics/<stable-topic-id>/`. В каждой папке свои AGENTS.md, memory/INDEX.md, BRIEF.md и
tasks/main/HANDOFF.md. Достаточно временного имени; окончательную цель и категорию не выдумывать.
Стабильный ID сохраняется при переименовании. Храни только подтверждённые факты, вопросы и следующий шаг темы.
Один общий inbox-handoff не должен смешивать независимые разговоры. Реестр хранилища содержит только
запрошенную навигацию; это не общий личный профиль и не разрешение читать другие записи.
Установленным темам не нужна повторная настройка; отдельная задача нужна только для самостоятельной цели.

## Продолжение в другом чате или ИИ-системе

Выбери папку этой темы или проверенную переносимую копию, не всё личное хранилище. Передай агенту:

> Работай только с переданной темой. Прочитай AGENTS.md, memory/INDEX.md, memory/BRIEF.md и handoff
> выбранной задачи. Восстанови текущую цель, подтверждённые решения, неизвестное и следующий шаг; сохрани WIP.
> Не открывай соседние темы, общий профиль и внешние материалы по ссылкам без относящегося к ним запроса.

Агент сверяет идентичность темы, папку/копию, даты/источники и фактический остаток. Если клиент не
обнаруживает AGENTS.md, инструкции передают явно. Прошлый чат восстанавливается только в пределах
сохранённого. При вложениях только на чтение верни точное предложение правок для ручного сохранения;
не объявляй запись выполненной. До правок из нескольких клиентов выбери одну текущую изменяемую копию.

## Перенос или объединение выбранных тем

Назови точные источник и назначение; объединение требует доступа к обеим темам. Если путь не указан
или недоступен, уточни его, не ищи соседей. До переноса/объединения сохрани исходные файлы,
незавершённое и происхождение данных; неизвестный файл не считается ненужным.
При переносе сохрани ID темы, обнови затронутые относительные ссылки/текущий вход и привязку папки клиента.
При объединении выбери одну текущую тему и согласуй факты/решения с источниками/датами.
Не перезаписывай конфликтующий файл и не выбирай истину по свежей дате. Сохрани обе версии до
решения пользователя по существенному противоречию; неразрешённый факт остаётся неизвестным. Обнови
затронутые индексы/handoff, явно обозначь старые записи заменёнными с указанием назначения. Указатель
не расширяет доступ. До завершения использования источника проверь ссылки и продолжение из назначения.
Оригиналы хранятся до проверки сохранности и восстановления; без автоудаления и переписывания истории.

## Устаревшие факты и архив

Важные факты храни с источником/датой и статусом: подтверждён, гипотеза, заменён или неизвестен.
Новая беседа или дата файла сами по себе не отменяют факт. Проверяй только значимое для текущего
запроса; противоречия/истечение срока указывай явно с сохранением происхождения и истории.
Не повторяй факт в BRIEF, handoff и сессиях. Краткая запись сессии нужна только при пользе.
Архивируй отметкой неактивной задачи/темы в её текущем индексе со ссылками на сохранённый итог,
открытые вопросы и условие продолжения; по умолчанию файлы остаются на месте. Физический перенос —
отдельное выбранное действие с проверкой ссылок/привязки. Не читай архивные темы при обычном старте
и не удаляй по возрасту. При возобновлении проверь актуальность прежних решений через текущий вход.

## Переносимая копия и облако

Используй текст UTF-8 и относительные ссылки внутри одной выбранной темы; включай необходимые
для продолжения документы по её внутренним ссылкам. Недоступные внешние входы укажи пробелами;
не экспортируй другие темы по ссылкам и не скачивай облачные источники автоматически. Исключи секреты,
общие профили, служебную память координатора, посторонние темы и приватные логи; до передачи проверь
точный список файлов и содержимое. Синхронизация/загрузка в облако и права получателя/провайдера
требуют выбранного назначения и текущих полномочий. Публичный репозиторий ОКПИ не является личным
хранилищем. Исключение папки/ZIP само по себе не проверяет содержимое.

Для передачи сохрани точку продолжения и прекрати параллельные записи; копируй только выбранные
файлы, сравни содержимое/хеши и проверь локальные ссылки. Обозначь текущую копию, ревизию/источник другой.
Конфликт синхронизации сохраняет обе версии; согласуй изменения до продолжения, без last-write-wins.
Ссылки на каталоги/symlinks и абсолютные пути не должны незаметно добавлять внешние материалы.
Без необходимых файлов по ссылкам или записи укажи неполную/ручную передачу; не объявляй полное восстановление.

Папки и инструкции ограничивают предполагаемый контекст, не технический доступ. Отдельно проверь
разрешённые папки клиента, подключённые источники, общий доступ и автоматическую память, не открывая
для проверки другую тему. Markdown и синтетические файловые проверки не сертифицируют поведение облака/провайдера.

## Долгое ожидание или прерывание

Различай выполнение, ожидание названного внешнего события и отсутствие наблюдаемого прогресса;
тишина не доказывает зависание. В текущем handoff сохраняй ID/cursor операции, последние данные,
остаток и следующее событие/check. Продолжай ту же операцию, не запускай дубликат после восстановления.
Ограничь интервал/срок наблюдения; без местного правила после трёх неизменных опросов за ход сохрани
точку продолжения. Без незапрошенных уведомлений, мониторинга по расписанию и фоновой работы.
